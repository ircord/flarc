## Evidence and reproduction

Tests are executable local reproductions; use `bun run test:security`. [boundaries.test.ts](../../tests/security/boundaries.test.ts) creates **independent Alice, Bob, Charlie and AuditAdmin accounts and bearer credentials**, plus distinct IRC device nicknames. It never treats changing a request's username as authenticating a second identity.

Representative original exploits were public `POST /api/v1/auth/register` with `roles:["admin"]`, administrative requests with `X-User`, nickname-only IRC messaging, SASL EXTERNAL with an account name and no certificate, querying another pair's DM history, public event handshakes, and cross-author edit/redaction operations. Current tests assert their denial alongside legitimate access. All `s/p/i/k` channel modes have independent outsider history/metadata/discovery checks. Transport checks cover IRC writes → REST reads, REST writes → IRC delivery, event isolation, kicks/bans, and account/session changes.

[storage.test.ts](../../tests/security/storage.test.ts) inspects actual workerd SQLite files while the runtime is stopped, then restarts an independent runtime. It verifies credentials, token hashes, profiles, memberships, channel data, messages, edits/redactions/FTS, roles/FKs, markers, preferences, subscriptions, private media, expiry, and injected write failure rollback. The rename failure test aborts a real destination INSERT and checks that no partial destination name/founder/history was committed and the original channel remains writable.

[crypto-and-egress.test.ts](../../tests/security/crypto-and-egress.test.ts) checks RFC 7677's published SCRAM exchange using independent Node PBKDF2, malformed proofs/verifiers, random salts, rejected egress destinations, private redirect refusal and streamed byte limits. Egress response tests use a controlled fetch double; they do not establish live DNS behavior.

[api-contract.test.ts](../../tests/security/api-contract.test.ts) checks client-route/method coverage against OpenAPI and critical session/registration contracts. Independent conformance source files were not modified. See [exact results](security-test-results.md).

## Authentication and data-access decisions

API sessions use random 256-bit bearer credentials, SHA-256 hashes at rest, 24-hour expiry and a 20-session/account bound. A current account record supplies permissions on each verification. IRC attaches account ID and credential version, rechecks them on commands, and is disconnected after password reset/disable/delete. Passive IRC output also resolves the current account/version and channel read permission per ordered delivery batch, with bounded per-socket/global pending output. Event sockets attach only a hash reference and recheck the parent session and resource for every delivery. Bootstrap is consumed persistently; reserved names do not confer administrator status merely by logging in. Creating the first channel can assign that new channel's founder grant; login itself creates no channel grants.

Public history is authenticated-readable. `s`, `p`, `i` and `k` history, related metadata and scoped media require current/persistent membership or an explicit founder grant; bans deny ordinary reads. Administrators have explicit channel administrative authority. Authorized readers can read the full retained history predating their membership. Part/kick removes membership; an independent persistent founder grant remains until revoked. Custom roles and ChanServ access are read from authoritative channel state on every relevant operation.

DM records use immutable account pairs; only participants can read and only authors can edit/redact. No administrative DM override or group-DM API exists. Account deletion keeps other participants' retained history, reserves the old username, and does not cascade-delete channel messages. REST logout revokes its API token and associated event connections; independently authenticated IRC connections are separate sessions, revoked by account/credential lifecycle changes.

## Database and Durable Object review

Local foreign keys are enabled. Account credentials, nickname ownership and role assignments have real uniqueness/FK constraints; channel role assignment now uses Drizzle's actual `group_id` model, with FK cascade coverage. Administrator operations re-verify the API session and role at each owning-object allowlisted dispatcher. Canonical registration is rechecked in a synchronous transaction after cryptographic awaits. Password verifier/SCRAM/session revocation updates are atomic and a forced SCRAM INSERT failure rolls them back together. FTS triggers maintain consistency on insert/update/delete and rebuild old indexes once. Queries deny expired/redacted records before cleanup; alarms continue after no-op retention passes. Edit chains share their original expiry and redact together.

SQLite transactions stop at the object boundary. API idempotency keys prevent duplicate committed channel messages across concurrent retries. Commit and transient delivery are separate; history recovers messages after missed live delivery. Rename imports are locally transactional, reject existing destinations, transfer ACL/roles/edits, and freeze transitions. A destination SQL failure is tested. Uncertain failures after destination commit keep transition state for operator recovery rather than exposing partially moved private data. A distributed transaction or automatic durable outbox/recovery workflow is not claimed.

## Migration and rollout limits

Canonical identity migration is transactional and refuses ambiguous duplicates; it never merges accounts or deletes their history. Deleted usernames are tombstoned. Unowned legacy uploads, media without a channel generation, and old nickname-keyed DM rows are retained but not assigned to guessed owners. Recover ownership only from reliable historical evidence. New account-ID DMs remain readable by a surviving participant after deletion of the other account.

Existing privileged accounts/ACLs must be reviewed before rollout: code fixes cannot determine which old grants were legitimate or retract data already disclosed. Take a backup and rehearse on a copy of actual deployed databases; tests cover fresh databases and generated legacy-column upgrade paths, not an operator's historical dataset. `old/` does not exist in this checkout. No production deployment or destructive production migration was performed. Keep at least one recoverable administrator account and a tested backup: consumed bootstrap authority is deliberately not a password-reset or break-glass API.
